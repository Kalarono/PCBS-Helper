# Для разработчиков PCBS-Helper

Инструкция для игроков находится в [README.md](README.md). Этот файл описывает сборку из исходников, проверки и подготовку пакета.

## Сборка

Нужны Windows, установленная игра и BepInEx 5. Используется C# compiler .NET
Framework из Windows. DLL игры берутся **только из локальной установки**.
Все исходники калькулятора находятся в `assets/helper-calculator*`.
Загрузка стороннего HTML не требуется. HTML и JavaScript встраиваются в DLL как ресурсы; для установки мода
достаточно BepInEx 5 и `PCBS-Helper.dll`.

```powershell
.\Build.ps1 -GamePath 'D:\SteamLibrary\steamapps\common\PC Building Simulator' -Test
# Закройте игру, затем установите мод:
.\Build.ps1 -GamePath 'D:\SteamLibrary\steamapps\common\PC Building Simulator' -Install -Test
```

Можно задать `PCBS_GAME_PATH` или локальный, исключённый из Git `build.local.json`:

```json
{ "gamePath": "D:\\SteamLibrary\\steamapps\\common\\PC Building Simulator" }
```

Пакет: `build/package/PCBS-Helper/`. Файл `PCBS-Helper.dll` сам содержит
все файлы калькулятора. Скопируйте его в `BepInEx/plugins/PCBS-Helper/`.
Скрипт `Build.ps1 -Install` сохраняет заменяемые файлы в `build/backups/`
и не меняет игровые DLL или сохранения. Для удаления хелпера перенесите папку
PCBS-Helper за пределы plugins.

## Подготовка файлов релиза

```powershell
.\scripts\Package-Release.ps1 -GamePath 'D:\SteamLibrary\steamapps\common\PC Building Simulator' -Test
```

Скрипт собирает хелпер, загружает официальный BepInEx 5.4.23.5 для Windows x64
и проверяет SHA-256 архива. Для уже скачанного архива можно передать
`-BepInExArchivePath`. Установка в игру при подготовке релиза не выполняется.

В `build/release/<версия>/` появятся пять файлов для GitHub Releases:

- `PCBS-Helper-<версия>-Full.zip` — распаковка содержимого прямо рядом с `PCBS.exe`.
- `BepInEx_win_x64_5.4.23.5.zip` — неизменённый официальный архив загрузчика.
- `PCBS-Helper.dll` — установка или обновление при работающем BepInEx 5 x64.
- `README.txt` — самостоятельная инструкция на русском для обоих способов установки.
- `README_EN.txt` — такая же инструкция на английском.

Полный архив сохраняет все файлы официального BepInEx, добавляет лицензию,
обе инструкции и хелпер в `BepInEx/plugins/PCBS-Helper/`. Игровые DLL, конфиги,
логи и пользовательские данные в него не включаются.
Перед сменой версии обновите README.md, README_EN.md, README.txt и README_EN.txt;
скрипт проверяет версию в обеих TXT-инструкциях. Английский гайд для игроков
находится в README_EN.md, подробная справка на русском — в `docs/`.

## Собственный калькулятор

`GameCalculatorCatalog` читает каталог из `PartsDatabase` установленной PCBS.
В репозитории и DLL нет таблиц деталей, коэффициентов или HTML стороннего калькулятора.
`helper-calculator-engine.js` самостоятельно реализует расчёт 3DMark и подбор
сборок, апгрейдов и замен деталей. `helper-calculator-app.js` строит интерфейс.
Существующие адаптеры состояния, локализации и корзины сохраняют контракт моста.

В PCBS есть коэффициенты CPU и двух графических тестов для одной/двух GPU.
Расчёт использует 32-битную точность (`Math.fround`) и порядок округления игры.
Проверка `GameScoreOracle.cs` вызывает настоящие `PartDescCPU.Test` и
`PartDescGPU.Test` из игровой DLL; проверки не зависят от сторонних калькуляторов.
Оценка предполагает стабильные частоты без перегрева. Пустые поля частот используют
заводские значения. При импорте апгрейда учитываются текущие частоты BIOS.

Геометрия плат и корпусов читается по одному префабу за кадр; расчёт 3DMark
доступен до завершения загрузки. После подготовки разблокируются поисковые кнопки.
Локальный `BepInEx/config/PCBSHelper/game-geometry-cache.json` ускоряет следующий
запуск и инвалидируется при изменении файлов игры. Для изменённых префабов модов
кэш можно удалить вручную. Детали, зарегистрированные в игровой базе модами,
читаются из текущей установленной игры; каталог не содержит заранее упакованных
деталей неустановленного Hardware Expansion Mod.

Доступность покупок читается через `CareerStatus.IsPartUnlocked` и обновляется
при изменении карьеры. Вышеуровневые установленные детали остаются пригодными
для расчёта. Общие условия по марке применяются к покупаемым деталям; условия
по RAM/охлаждению и другим деталям вне апгрейда отдельно показаны для проверки.
БП, накопители, ремонт и стабильность разгона требуют проверки в самой игре.

Состояние сохраняет версию 1, прежние имена полей и историю. Новые поля частот
добавляются без удаления остальных вкладок. Импорт письма меняет только нужную
вкладку, а кнопка заказа использует прежний нативный мост корзины.

`embedded-ui.js` реализует меню select/datalist в offscreen Chromium.
`HelperLocalization.cs` и `calculator-localization.js` отвечают за язык интерфейса.
Управление F1/F2/F3, Alt, вводом и прокруткой не меняется.

`PurchaseByClick` отмечает строки `PCStatEntry.Init`, созданные внутри
`EmailJobDetails.OnPCStats`; Harmony finalizer сбрасывает контекст даже при
ошибке открытия. ЛКМ по строке вызывает `ClickPurchaseCart`: проверяются
`IsAvailableInShop`/`IsPartUnlocked`, создаётся новый `ShopEntry` и добавляется
в постоянную корзину `CareerStatus.GetShopTrolley`. Событие `Shop.s_updateTrolley`
обновляет уже открытые магазины. Оформление заказа и игровая установка деталей
не выполняются. Тесты корзины используют изолированные двойники API игры;
настоящие клики и обновление магазина проверяются отдельно в игре.
`calculator-build-order.js` заменяет действие строк Build Maker на «Заказать».
Сохраняется служебная `.buttonSave`/`save`-метка старой схемы состояния:
восстановленные результаты получают новые кнопки, прежняя история сохраняется.
Запрос `pcbsOrderBuild` содержит роли деталей, точные имена и количества;
`CalculatorBuildOrder` проверяет формат и находит модели в базе игры без
приближённых замен. Английское имя RAM восстанавливается из производителя,
названия, ёмкости и частоты, независимо от локализованной подписи.
Поиск исключает `PartDesc.Class.DUMMY` и детали вне магазина. Это устраняет
конфликты с реальными CPU, например `CPU_AMD_6` и одноимённым DUMMY Ryzen 1700.
Знаки ™/® и их повреждённое UTF-8 представление нормализуются вместе с
пробелами; номера моделей и варианты сохраняются. `CalculatorBuildOrder.AddAvailable`
добавляет каждую найденную доступную модель с её количеством. Ошибка одной
позиции не мешает остальным. Ответ `pcbsBuildOrderResult` содержит количество
добавленных деталей и массив `skipped` с именем, количеством и причиной.
Полностью и частично успешные ID кешируются: повтор после задержки ответа
не дублирует уже добавленные CPU/GPU.

Сопоставление с локальной базой игры (нужны UnityPy и beautifulsoup4):

```powershell
python tests/CompareGameCatalog.py --game-path 'D:\SteamLibrary\steamapps\common\PC Building Simulator' --output build/game-catalog/matching.json
```

Скрипт читает таблицы установленной игры и пишет только в исключённый из Git
`build/`. При наличии этой фикстуры `Build.ps1 -Test` проверяет сопоставление
CPU/GPU, корпусов, ОЗУ и плат с игровыми ID через код поиска хелпера. Базы игры в репозиторий и
релизный пакет не включаются.
Адаптер состояния задаёт 10 результатов для пустого поля и после Clear,
но сохраняет явно введённое число. Поля `pcbsFixed*` находятся в скрытых
строках формы: сохраняются и ограничивают поиск через импорт заказа.
Текст требований самого задания приходит из игры на языке переноса.
Сборка проверяет наличие всех ресурсов калькулятора и останавливается, если какой-то
отсутствует. При чтении встроенные ресурсы имеют приоритет над внешними файлами
от старых установок, поэтому оставшиеся HTML/JS/CSS не подменяют новую версию.

Исходники не включают DLL, базы игры или сохранения. Перед публичным релизом
выберите лицензию проекта. Сторонний HTML-калькулятор не используется; лицензия
BepInEx включается в полный пакет.

## Проверки

`JobHelperButton` размещает кнопки письма после штатного layout. Подпись
подгоняется под фактические границы своей кнопки с внутренним отступом,
включая вложенный `Text`: одного `resizeTextForBestFit` недостаточно,
поскольку клон наследует фиксированный размер подписи «Принять». При
временном сжатии штатных действий сохраняются и восстанавливаются обе
геометрии (кнопки и текста), выравнивание и режимы переполнения текста.

`WorkbenchAutomation` ставит Harmony-хуки на штатные состояния монтажа,
снятия и выбора кабеля. `DependencyRemoval` разрешает один следующий шаг
по текущим `Slot.CurrentBlockers`, динамическим коллизиям, дочерним слотам
и соединениям; перед демонтажем повторно вызывает `CanBeUninstalled`.
Составной `RAMSlot` раскрывается в две отдельные зависимости `CPin` на
открытие; уже открытые защёлки пропускаются. Это работает и для прямого
снятия памяти, и при демонтаже её родительской платы. Предупреждение о
водяном контуре требует обнаружения заполненного `WaterLoop` в обходе
зависимостей; неизвестная блокировка получает отдельное сообщение со ссылкой
на лог. Лог содержит цель, шаги очереди и обход блокировок при остановке.
Механизмы сокета `AM3Slot` и `LGASlot` имеют собственные `IsBlocked` и
`m_blockedBy`: их проверка обязательна перед `TogglePin`, а блокирующий
кулер разрешается как зависимость. Иначе попытка открыть сокет под кулером
сразу отменяет всю очередь вместо перехода к охлаждению.
`InstallingPartState`, `CableInstance`, анимации `Pin`, корутины
`AM3Slot.OpenSocket/CloseSocket` и `LGASlot.Update` приостанавливаются
без удержания ЛКМ. Начальное удержание 0,3 с проверяется один раз; между
зависимостями дополнительной задержки нет. Винты используют штатный
`Screw.Tighten`: 1x без улучшений, 4x с соответствующими улучшениями игры,
без установки `ForceFastWork` и без изменения игровых апгрейдов.
Esc отменяет очередь, а отмена текущего монтажа выполняется самой игрой.

Автоматическая термопаста вызывает `CPU.SetThermalPasteState` при установке
CPU в сокет и повторно при монтаже воздушного охлаждения, СЖО или водоблока,
если паста отсутствует. СЖО определяется по типу детали, поскольку игра
монтирует её через слот корпуса/радиатора и создаёт прокси в CPU cooler slot.
ЦП берётся из `Motherboard.cpuSlot`, пустые слоты и placeholder пропускаются.
Демонтаж и выключенный помощник не наносят пасту; штатное снятие кулера
по-прежнему её стирает. Нанесение записывается в лог с ID ЦП/детали и слотом.
Доступность перекраски проверяется по
`CableDesc` и фиксированному оформлению разъёма, независимо от истории кабеля.
Новая геометрия создаётся штатным `CableMesh.Init` на временном объекте и
переносится на существующий кабель вместе с коллайдерами. `CableInstance`,
штекеры, разъёмы и корневой renderer сохраняются; неудача возвращает исходное
оформление. Это исключает привязку новых кабелей к старым штекерам, ещё
ожидающим отложенного удаления Unity. При снятии зависимости вызываются
`Case.OnChangePart` для самого кабеля и штатный `CableInstance.Uninstall`.

`InventorySorting` сортирует только `m_itemsPendingCreation` до создания
карточек и после нативных фильтров. Цена — `GetResaleValue`; поступление —
индекс экземпляра в сохранённом списке инвентаря. Список сохранения не
переставляется. Кнопки находятся в `InventoryPanel`, поскольку корневой
RectTransform `Inventory` имеет нулевой размер. `Build.ps1 -Test` проверяет
алгоритмы очереди/сортировки и контракты API/IL локальной игры через Mono.Cecil.
Сценарии в игре: [tests/MANUAL-WORKBENCH.md](tests/MANUAL-WORKBENCH.md).

Для проверки собственного калькулятора:

```powershell
# Без запуска игры: нужны UnityPy и beautifulsoup4. Геометрия в этой фикстуре условная.
python tests/ExportCalculatorFixture.py --game-path 'D:\SteamLibrary\steamapps\common\PC Building Simulator' --output build/game-catalog/helper-catalog.json
./scripts/Test-Calculator.ps1 -GamePath 'D:\SteamLibrary\steamapps\common\PC Building Simulator'
```

Для проверки настоящей геометрии включите диагностический параметр
`ExportCalculatorCatalog` в конфиге хелпера и откройте F2. После завершения
подготовки файл `BepInEx/config/PCBSHelper/game-calculator-catalog.json` содержит
данные работающей игры. Передайте его скрипту через `-CatalogPath`.
В этой сессии проверено 4738 эталонных расчётов CPU/GPU и 24 дополнительных
проверки подбора/ограничений на каталоге, прочитанном в работающей PCBS.
`Build.ps1 -Test` также запускает эти проверки, если локальная фикстура уже есть.

F3 сохраняет эталоны из Will it Run? в основной таблице. `JobRequirementReader`
читает параметры реальных целей, включая скрытые пожелания из письма,
через поля `UseBrandObjective`, `EsportsPartMustBeBrandObjective`,
`InstallPartObjective`, `RamObjective` и `StorageObjective`. Перечень остальных
уточнений ограничен условиями оборудования и оформления. Текст письма не
разбирается по словам: упоминание старого оборудования не становится новым условием.

`RequirementClarifications` скрывает условия, уже покрытые выбранным профилем,
и подбирает CPU/GPU при расхождении. Используются реальные `CPU.Test()` и
`GPU.Test()`, объём VRAM и текущая доступность деталей. Общий бренд получает
CPU/GPU-варианты из каталога даже при неоднозначной категории (AMD, EVGA),
а каждый вариант отдельно фильтруется по нужному производителю. Для общего
AMD/Intel при наличии достаточного CPU показывается прежде всего процессор;
если он недоступен, возможен GPU-вариант. Явные GPU-цели не меняют категорию.
Два варианта для общего бренда — способы выполнить условие одной новой
деталью; несколько деталей требуют ручного подбора сочетания. Ограничения
производителя GPU не подменяются маркой чипа. Все ограничения на выбранную
деталь применяются одновременно. Сложные условия по разгону, апгрейду,
водоблоку, отдельной цели 3DMark и двум GPU остаются видимыми с ручным выбором детали.
Обычный `INSTALL_PART` допускает лучшую игровую Quality; DLC specific-part
требует точный ID. Закреплённая панель хранит связь с собственным заказом,
а ручной выбор игры не наследует его условия. Смена языка обновляет описания.

`Build.ps1 -Test` проверяет конфликты CPU/GPU, точное равенство порогу,
VRAM, цену, фильтр уровня, запреты брендов, несколько одновременных условий,
подсказки RAM/HDD и отсутствие лишнего блока. `JobRequirementReaderTests`
читает реальные классы целей из локальной игровой DLL: сериализованные поля
создаются без конструкторов, загрузки Unity и сохранений. Проверка интерфейса
и сценарии заказов описаны в [tests/MANUAL-F3-CLARIFICATIONS.md](tests/MANUAL-F3-CLARIFICATIONS.md).

Результаты ручной проверки: [tests/INTEGRATION.md](tests/INTEGRATION.md).
Тесты позиции окон дополнительно проверяют сериализацию, восстановление на том
же разрешении, перенос на другое разрешение, ограничение экраном и повреждённые значения.
Тесты также проверяют вычисление уровня/процента опыта и независимое сохранение
и очистку вкладок калькулятора. Изолированная браузерная проверка проверяет
настоящий расчёт 3DMark, Clear и восстановление страницы после перезагрузки;
она не заменяет проверку встроенного браузера в игре.
